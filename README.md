# Agentic 多模态 AIGC 游戏素材生产与评估系统

本项目面向统一画风游戏素材的批量生产，将“训练出一个会画 MTG 风格的模型”推进为“能够理解需求、发现低质量结果、自动补救并稳定交付的生成系统”。

项目分为两个递进阶段：

- `gen_project`：解决基础模型对目标画风掌握不足的问题，完成数据构建、LoRA 微调和受控验证；
- `asset_pipeline`：解决生成需求不明确、结果随机波动、后处理副作用和长批次易中断的问题，完成生产化编排与验收。

```text
公开 MTG 图文数据
        ↓
数据清洗与 Caption 配对
        ↓
SD1.5 + LoRA 风格适配
        ↓
自然语言需求 → Agent 结构化 Prompt
        ↓
ComfyUI / Stable Diffusion 批量生成
        ↓
CLIP 质量门 → 低分样本换 seed 有限重试
        ↓
Real-ESRGAN 超分 → 最终复评
        ↓
manifest + state → 可追溯、可恢复交付
```

## 1. 为什么先做数据与 LoRA

### 动机

Stable Diffusion 1.5 具备通用文生图能力，但仅靠在 Prompt 中加入“MTG card art style”，无法稳定复现目标卡图的构图、色彩和幻想插画质感。直接全量微调成本较高，也不利于快速验证风格适配是否有效，因此采用 LoRA。

### 数据处理

从公开数据集 `TrevorJS/mtg-scryfall-unique-artwork-20240809-with-card-art-descriptions-and-images` 中选取 3000 组 MTG 卡图及 Caption，经过尺寸检查、坏图过滤、dHash 去重和统一裁剪，得到 2935 组有效图文对，并固定划分为 2348 组训练数据与 587 组评估数据。

Caption 是训练阶段与图片配对的文字监督。若清洗或重命名后发生图文错位，模型即使正常收敛，也会学习错误的语义对应关系。因此流水线使用稳定样本 ID 维护映射，并检查缺图、缺 Caption、重复 ID 和划分交叉。

### LoRA 原理与选择

LoRA 冻结基础模型权重，只学习低秩增量：

```text
W' = W + BA，且 rank(BA) 远小于 W 的维度
```

本项目在 SD1.5 U-Net Attention 层进行 rank-16 LoRA 微调。这样既保留基础模型的通用生成能力，又以较低显存和存储成本注入 MTG 风格。

验证 LoRA 时固定 Prompt、生成数量和评测流程，只改变是否加载 LoRA。受控实验表明 CLIP-Score 提升约 2.5%，FID 下降约 7.0%，用于证明风格微调有效；它不代表完整生产系统已经完成。

## 2. 为什么需要 Agent 改写 Prompt

### 动机

业务需求通常只有“画一个喷火巨龙”这类自然语言描述，但扩散模型还需要主体属性、动作、景别、环境、光照、配色和画风等视觉条件。固定模板成本低且稳定，却难以覆盖开放需求；逐图调用大模型又会增加费用、延迟和不可复现性。

### 技术方案

系统使用 DeepSeek Function Calling 将自然语言需求解析为受 Schema 约束的结构化任务，补齐：

```text
主体 + 属性/动作 + 构图/景别 + 环境 + 光照 + 配色 + 材质/风格
```

Agent 只负责“业务语言到视觉语言”的转换以及工作流选择，不负责生成图像。批量任务采用场景级规划和批次内复用，再结合不同 seed 产生变化，避免为每张图片重复调用 API。

Function Calling 输出经过字段校验、默认值补齐和失败重试后，才能进入 ComfyUI，防止自由文本格式变化直接破坏执行链路。

## 3. Stable Diffusion 实际如何生成图像

Stable Diffusion 不从一张黑图开始，而是从由 seed 确定的高斯随机 latent 开始。latent 是包含正负随机值的低维张量，本身没有“巨龙、骑士”等目标信息。

```text
seed → 初始高斯噪声 latent
Prompt → Text Encoder → 文本条件
基础模型 + LoRA → 通用视觉知识与目标风格
U-Net + Cross-Attention → 条件噪声预测
Scheduler → 逐步更新 latent
VAE Decoder → RGB 图像
```

若采样步数设为 28，系统会重复约 28 次“读取当前 latent、时间步和文本条件 → U-Net 预测噪声 → Scheduler 更新 latent”，最后才由 VAE 解码成一张图片。

seed 是伪随机数生成器的起点。相同模型、Prompt、参数和 seed 用于复现采样轨迹；更换 seed 会改变初始噪声，因此可能改变构图、姿态和局部细节。

## 4. 为什么用 ComfyUI 承载生成工作流

### 动机

训练代码适合模型实验，但不适合长期维护多种生成与后处理链路。把业务编排、模型推理和工作流配置耦合在一个 Python 脚本中，会导致更换节点或参数时修改面过大。

### 技术方案

系统将职责拆分为：

- Python 编排器：解析任务、选择工作流、提交请求、轮询结果、评分和记录状态；
- ComfyUI：加载 checkpoint/LoRA，执行 GPU 推理和节点工作流；
- JSON 工作流：保存可配置的模型、采样与后处理拓扑。

当前提供四条 API 工作流：

- `wf_txt2img`：文本直接生成；
- `wf_img2img`：基于输入图进行受控重绘；
- `wf_ipadapter`：利用参考图视觉特征约束生成；
- `wf_post`：Real-ESRGAN 超分。

启动正式任务前先校验工作流节点是否在 ComfyUI 注册，再用真实出图做冒烟测试。节点名称存在不等于模型一定可加载，所以验收必须落到端到端图片产物。

## 5. 为什么设置质量门并换 seed 重试

### 动机

扩散采样具有随机性：Prompt 和模型不变，同一场景仍可能生成主体不清或语义偏离的结果。若将所有图片直接交付，人工挑图与返工成本会随批量规模增长。

### 技术方案

系统使用 open_clip ViT-B-32 计算生成图与 Prompt 的 CLIP-Score：

```text
候选图 → CLIP-Score
       ├─ 达到阈值：进入后处理
       └─ 低于阈值：更换 seed 重新采样
```

换 seed 不改变业务需求与模型，只改变初始噪声，是成本较低的失败修复方式。系统同时限制最大重试次数，避免为了极少数困难样本造成无限算力消耗和尾部延迟。

需要注意：用 CLIP 选图后再报告 CLIP，分数上升包含选择效应。因此该机制只能证明“按既定语义规则减少低分交付”，不能直接等价为人类审美全面提升。更完整的产品验证应增加独立审美模型或匿名人工盲评。

## 6. 为什么加入 Real-ESRGAN，又为什么必须复评

### 动机

扩散模型的原始输出可能存在边缘发软、局部纹理不足等问题，展示素材通常还需要更高分辨率，因此接入 Real-ESRGAN。

### 原理与边界

Real-ESRGAN 使用公开预训练的生成式超分权重 `RealESRGAN_x4plus.pth`。本项目负责集成和验收，没有训练该超分网络。

它不同于普通插值：网络利用图像先验重建轮廓和高频纹理，因此可能让主体更清晰；但补出的细节也可能是假纹理，甚至改变生成图相对真实参考集的特征分布。

正式验收中，超分后的平均 CLIP-Score 有所提高，但 FID 由 172.25 上升到 183.07。系统因此保留超分前后的两版图片并重新评分，不把超分默认包装成全面提升：展示场景可以偏向清晰度，强调分布真实性时可以回退原图。

## 7. 为什么需要断点续跑和可追溯清单

### 动机

几百张生成任务持续时间较长，期间可能遇到服务重启、网络中断或单样本失败。若只保存最终图片，系统无法判断哪些任务已完成，也无法解释某张图为什么被选中。

### 技术方案

每个批次维护：

- `state.json`：记录任务状态，续跑时跳过已完成项，只处理未完成或失败项；
- `manifest.json`：记录需求、详细 Prompt、seed、尝试次数、阶段评分、耗时和输出路径；
- 原图/后处理图：保留阶段产物，支持复评和回退。

这种设计把长批次从“一次性脚本”变成可恢复任务：失败不会污染完成集合，使用同一批次 ID 可以继续运行，并能够对单张结果进行回放与问题定位。

## 8. 实验为什么分成两个阶段

### 阶段一：模型能力验证

目标是回答“LoRA 是否有效”。基础模型与 LoRA 使用相同 Prompt、样本规模和评测流程，形成单变量受控比较。

### 阶段二：生产系统验收

目标是回答“Agent、生成、筛选、重试、超分和恢复组成的系统能否稳定交付”。正式批次覆盖 6 类需求，共交付 600 张图片；首次质量通过率为 91.3%，有限重试与复评后为 99.5%。

两阶段形成“风格学得会 → 系统交付稳”的递进证据，但不能把阶段一 LoRA 分数与阶段二生产分数直接当作同协议连续消融，也不能把生产阶段的全部变化单独归因于 Agent。

600 张是内部生产验收，不等同于论文常见的 FID-50K，也不足以单独证明工业级 SLA。真正工业化还需要持续流量、并发压测、成本监控、安全审核、灰度发布和长期漂移监控。

## 10. 快速运行

### 前置检查

```bash
cd ~/yl/aigc/asset_pipeline
bash scripts/test_wf.sh
```

该脚本检查 ComfyUI API、checkpoint、工作流节点及端到端出图能力。环境安装与故障排查见 [ComfyUI 部署说明](comfyui/README.md)。

### 小批量端到端验证

```bash
bash scripts/run_e2e.sh "做 3 张 MTG 风格的中国风武将卡牌图"
```

### 正式生产验收

```bash
nohup bash scripts/run_production_benchmark.sh > production_benchmark_600.log 2>&1 &
tail -f production_benchmark_600.log
```

结果位于 `deliverables/production_600_*/`，核心文件包括 `summary.json`、`manifest.json`、`state.json` 和最终图片。

## 12. 当前能力边界

- 600 张正式生产批次以 txt2img 为主；img2img、IP-Adapter 和后处理链路完成了冒烟验证；
- 当前 `wf_post` 负责 Real-ESRGAN 超分，未正式启用自动去背景；
- CLIP-Score 是语义一致性指标，不等价于人工审美或商业可用性；
- Real-ESRGAN 使用公开预训练权重，不属于自行训练的模型；
- 项目完成的是内部生产验收，不宣称达到行业最优或工业级 SLA。
