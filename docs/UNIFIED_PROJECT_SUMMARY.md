# Agentic 多模态 AIGC 游戏素材生产系统

## 1. 项目定位

这是一个从模型研发到生产验收的递进式个人项目，不是两个相互竞争的项目。

- 阶段一 `gen_project`：解决“模型能否学到目标美术风格”，完成数据构建、Stable Diffusion 1.5 LoRA 微调、基座对照与离线评估。
- 阶段二 `asset_pipeline`：解决“模型能否稳定、自动、可恢复地交付素材”，完成 Agent 需求拆解、ComfyUI 工作流调度、质量筛选、失败重试、Real-ESRGAN 超分、最终复评与批次报告。

统一问题定义：给定自然语言或参考图需求，自动生成风格一致、语义匹配且具有可追溯质量记录的游戏卡牌素材。

## 2. 端到端架构

```text
MTG 图文数据
  -> 清洗去重/裁剪/划分
  -> SD1.5 + LoRA 风格微调
  -> CLIP-Score/FID 基座对照
  -> DeepSeek Function Calling 解析自然语言需求
  -> ComfyUI 调度 txt2img/img2img/IP-Adapter
  -> CLIP-Score 质量门，不达标换 seed 重试
  -> Real-ESRGAN 超分
  -> 最终图再次评分
  -> manifest.json/state.json/summary.json 批次交付
```

系统默认使用单个 ComfyUI 服务即可运行；多 worker 仅是可选吞吐扩展，不是项目成立的前提。

## 3. 已完成结果

### 3.1 阶段一：风格 LoRA 训练与对照

| 项目 | 结果 |
|---|---:|
| 原始图像 | 3,000 张 |
| 清洗后有效图像 | 2,935 张 |
| 训练集 / 评估集 | 2,348 / 587 |
| 生成评估集 | 6 个 Prompt x 16，共 96 张 |
| SD1.5 基座 CLIP-Score | 0.33772 |
| LoRA CLIP-Score | 0.34609，较基座 +2.5% |
| SD1.5 基座 FID | 235.92 |
| LoRA FID | 219.49，较基座下降 7.0% |

结论：在同一批 Prompt 与评估口径下，LoRA 同时改善了文图对齐和与真实卡图的特征分布距离，证明风格微调有效。96 张属于模型研发阶段的小规模对照，不宣称等同于 FID-50K。

### 3.2 阶段二：生产链路验证

已完成：

- ComfyUI 0.7.0、PyTorch 2.5.1+cu121 与 NVIDIA A40 环境验证。
- `wf_txt2img`、`wf_img2img`、`wf_ipadapter`、`wf_post` 四个工作流节点校验全部通过。
- 四工作流冒烟全部成功出图。
- 3 张端到端样例全部交付，CLIP-Score 分别为 0.3950、0.3514、0.3205，均超过 0.30 门槛，均值 0.3556。
- 逻辑层 13 项测试通过，覆盖 Agent 输出校验、质量判断、多 worker 调度与失败项断点重试。

当前正式生产验收：6 类需求 x 100，共 600 张；完整经过 Agent、质量门、重试、超分和最终复评。实验正在服务器执行，最终数值只能从 `summary.json` 回填。

## 4. 正式验收指标

最终报告应包含以下指标，不只展示“好看的样图”：

- 交付成功率及 Wilson 95% 置信区间。
- 首轮原始分、质量门选中分与超分后最终分。
- CLIP-Score 均值及 Bootstrap 95% 置信区间。
- 质量门带来的分数提升、超分前后变化。
- 实际生成次数、额外尝试次数、平均重试次数。
- 平均/P50/P95 端到端延迟与吞吐量。
- 6 类场景分项结果。
- 质量门原图 FID 与最终图 FID，口径标为 `FID-600 internal acceptance benchmark`。

600 张的目的不是模拟论文常用的 50K 规模，而是在求职项目可承担的算力成本内，给出比 96 张更稳定的生产验收证据。

## 5. 关键工程设计

### Agent 规划而非逐图调用

DeepSeek 对 6 个场景各调用一次，将自然语言需求转换为结构化任务；随后由本地代码确定每类总量并扩展到 600 张。这样既保留 Agent 的需求理解能力，又避免 600 次重复 API 调用，提高可复现性并控制成本。

### 工作流与模型解耦

编排器只负责结构化任务、参数填充、调度和状态管理；ComfyUI 负责实际推理。四个 JSON 工作流独立校验，便于替换 checkpoint、LoRA、IP-Adapter 或后处理模型。

### 质量闭环

每次生成后使用 open_clip ViT-B-32 计算文图相似度；低于阈值时更换 seed，最多重试 3 次。选中图经过 Real-ESRGAN 后再次评分，避免默认假设“超分一定提升语义质量”。

### 可恢复交付

每完成一项就更新 `state.json`；失败项不写入 done 集合，同一 `batch_id` 重启时只重试失败或未完成项。`manifest.json` 保存 Prompt、seed、尝试记录、分数、耗时和最终文件路径。

## 6. 边界与诚实表述

- 当前 `wf_post` 已验证的是 Real-ESRGAN 超分，不能宣称已经自动去背景。
- 生产验收受 Agent 改写、质量选择和后处理共同影响，不能把阶段二与阶段一的差值全部归因于某个单一模块。
- CLIP 既作为质量门又作为报告指标会产生选择偏差，因此同时报告 FID、成功率、重试成本和样例网格；若继续扩展，可加入盲评或独立 DINO/美学评分器。
- A40 数量只属于运行环境信息。默认单实例可完成实验，多卡并行不属于本项目结论。

## 7. 项目交付物

- 模型研发：数据清洗、caption 对齐、LoRA 训练与 base/LoRA 评估脚本。
- 推理工作流：txt2img、img2img、IP-Adapter、Real-ESRGAN 后处理。
- Agent 编排：Function Calling、Schema 校验、退避重试。
- 生产能力：质量门、换 seed 重试、断点续跑、结构化批次交付。
- 评估能力：CLIP/FID、置信区间、分位延迟、吞吐、场景分项与消融口径。
- 工程保障：工作流节点校验、冒烟、端到端验证和逻辑单测。
